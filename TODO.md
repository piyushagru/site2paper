# Roadmap

Priorities:

- **P0**: breaks a promise the README makes, blocks public use, or is a licence or attribution requirement.
- **P1**: a clear need with a cited source, a gap found in the code, or an item the owner asked for.
- **P2**: competitor parity or a nice-to-have.

Tiers: **T1** under 50 changed lines, **T2** 50 to 200 lines, **T3** needs an owner decision before code (new format, new config surface, new dependency, release or publish step).

Vision: one command that turns any website into the print, text and screenshot outputs people need, with the same zero-config start.

- **P2-23 A cut can land between two lines of one paragraph.** `snap()` in `src/book.mjs` returns the first flat row it meets walking up from the cut, and `describe()` in `src/capture.mjs` marks a row flat when its grey range is under 6, so the 4 to 10 px gap between two text lines at 1440 px qualifies as well as a 40 px gap between cards; the column break then splits a sentence, which the README's "cut on the nearest blank row" promise does not intend. Smallest fix: in `snap()`, prefer the nearest run of at least 12 flat rows inside the 600 px window and cut at its middle, fall back to any flat row; one unit test on an exported `snap` with a map that has a 6-row gap near the cut and a 20-row gap further up. - **P2-24 Two colours of equal brightness read as one flat row.** `describe()` in `src/capture.mjs` works on the greyscale image, so a row where a saturated red block meets a green one of the same luminance scores a range under 6 and is offered as a cut; the next column then opens in the middle of a coloured band. Hypothesis on how often a site puts equal-luma colours side by side; the fix is five lines. Tier T1. Source: gap found reading `describe()` against `snap()` in `src/book.mjs`, deep dive 2026-11-14.
- **P2-25 The sheet number runs past the right margin after 99 sheets.** `buildBook()` draws `${i + 1}/${sheets.length}` at `x: sheet.width - sheet.margin - 20` at 7 pt, about 17 pt for `10/20` and 24 pt for `100/120`, so three-digit books print the counter 4 pt into the margin, still on the sheet. Smallest fix: right-align with `font.widthOfTextAtSize`, two lines, no test needed beyond the existing book test. Tier T1. Source: `sheetFor()` margins in `src/layout.mjs`, deep dive 2026-11-14.
- **P2-11 New-user smoke on Linux without Chrome.** The Chromium download path and Linux have never run from the packed tarball as a new user; the local container runtime did not start on 2026-11-11. Add a CI job on ubuntu with no Chrome that runs `npm run smoke`. Tier T2.
- **P2-15 `<loc>` wrapped in CDATA is skipped.** `parseSitemap()` matches `<loc>\s*([^<\s]+)`, so `<loc><![CDATA[https://...]]></loc>` (emitted by some generators) matches nothing: the sitemap is found, zero pages come out, and the crawl runs instead. Smallest fix: accept an optional `<![CDATA[` ... `]]>` wrapper in the regex and decode `&amp;` in the URL, with one parse test per shape. Hypothesis on how common CDATA is; the fix is five lines. Tier T1. Source: [sitemaps.org protocol](https://www.sitemaps.org/protocol.html) (entity escaping of `<loc>`), deep dive 2026-11-12.
- **P2-18 Index children on another host are fetched.** `sitemapUrls()` in `src/discover.mjs` keeps only `Sitemap:` lines on the start origin, but `fromSitemap()` fetches every `<loc>` of a sitemap index as given, so an index that points at a CDN host or a stale old domain sends requests off the start origin before any URL is filtered; the protocol says child sitemaps must sit on the same site as the index. Smallest fix: skip an index child whose origin differs from the start origin, with one unit case; `fetchText` follows redirects, so also compare `res.url` after the fetch (deep dive 2026-11-14). Tier T1. Source: [Google, large sitemaps](https://developers.google.com/search/docs/crawling-indexing/sitemaps/large-sitemaps.md.txt) ("referenced sitemaps must be hosted on the same site as your sitemap index file"), deep dive 2026-11-13.

- **P2-26 A plain-text sitemap yields zero pages.** The protocol allows a sitemap that is a text file with one URL per line, and `robots.txt` may name it (`Sitemap: https://x.test/sitemap.txt`); `fetchText()` reads it fine, but `parseSitemap()` in `src/discover.mjs` finds no `<loc>`, so the run prints `No sitemap pages, crawling links instead` while the whole page list sat in hand. Source: [sitemaps.org protocol, Other Sitemap formats](https://www.sitemaps.org/protocol.html) ("text file" and `<loc>` of an index "can be a Sitemap, an Atom file, RSS file or a simple text file"), deep dive 2026-11-15.
- **P2-27 Sitemap URLs that differ only by their query collapse into one page.** `normalize()` in `src/discover.mjs` clears `url.search` for every URL, which is right for crawled links (`?utm_source=`, `?ref=`) but wrong for a sitemap: its `<loc>` values are the owner's canonical list, so `/products?page=2` and `/products?page=3` fold into `/products` and a paginated listing or a `?lang=fr` site prints page 1 only, with `Found N page(s) from sitemap` showing fewer than the sitemap holds. Smallest fix: `normalize(href, base, { keepQuery })`, true from `keep()` in `fromSitemap()` only, and decode `&amp;` in the loc first (P2-15 shares the line); one case with two `?page=` locs. Tier T1. Source: [sitemaps.org protocol](https://www.sitemaps.org/protocol.html) (`<loc>` is the full URL and `&` must be entity-escaped, so query strings are an expected shape), deep dive 2026-11-15.


## Needs decision

- **Honour `robots.txt` `Disallow` while crawling.** `crawl()` in `src/discover.mjs` follows every same-origin link, and `sitemapUrls()` reads `robots.txt` only for `Sitemap:` lines, so a crawl prints `/cart`, `/search?q=` or `/admin` pages the owner marked off-limits to bots. A print tool arguably acts for the visitor, not a bot, and AGENTS.md promises the site as visitors see it; honouring `Disallow` for `User-agent: *` changes which pages land in the PDF with no flag to override. Source: [robots.txt vs sitemap.xml](https://tools.town/learn/seo-tools/sitemap-vs-robots-txt/), deep dive 2026-11-15. Owner decision.
- **Redirect and private-network check before each navigation.** Same feedback, 2026-11-12: same-origin crawling is not a network safety boundary. A redirect or a DNS change can send a public URL to localhost or a cloud metadata address. Today nothing checks `page.url()` after `goto`, and no address range is blocked. Only matters for a hosted service or untrusted URL lists; the local CLI runs with the user's own network rights. If either lands: resolve the host before each request, refuse loopback, link-local and private ranges, and never log session cookies or bundle auth-walled captures into shared reports. Owner decision. Issue: https://github.com/piyushagru/site2paper/issues/3
- **Publish workflow.** Context seen 2026-11-09: trusted publishing now allows several trusted-publisher configs per package and holds staged versions until npm's malware scan completes (GitHub Changelog 2026-09-03, via https://www.refontelearning.com/blog/npm-multi-trusted-publishing-release-governance); the keyv@6.0.0 (2026-08-04) and @tanstack (2026-05-11) incidents show provenance attests the build, not the source, https://ecorpit.hashnode.dev/npm-provenance-signed-the-malware-on-4-august-2026-what-attestations-prove-and-what-a-cooldown-stops. Official docs: https://docs.npmjs.com/trusted-publishers. Added 2026-11-10: the GHAPPIER loader attack (2026-09-09) turned push access into publish access by editing a trusted-publishing release workflow, so the workflow file itself needs branch protection, https://orca.security/resources/research/ghappier-loader-npm-supply-chain-attack/. `docs/RELEASING.md` describes `.github/workflows/publish.yml` for trusted publishing, but the file does not exist. Adding it is a release-path change. Owner decision.
- **Text output for LLM and RAG use.** Competitor parity with `site2pdf`, which extracts page text. This is a new output format and a new output contract. Source: https://github.com/laiso/site2pdf. Owner decision.
